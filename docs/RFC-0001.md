# RFC-0001: Value Accord Protocol — Core Payment Flow

Status: **Draft 0.1**  
Specification licensing: **undecided; requires final legal review before publication or standards adoption.** Code samples remain Apache-2.0.

## Abstract

VAP defines an implementation-neutral exchange for declaring a destination-denominated payment intent, receiving comparable route quotes, authorizing one route with a single-use signed Value Packet, and producing a settlement receipt. VAP coordinates participants; it does not prescribe a ledger, asset, custody model, or settlement rail.

## Roles

- **Payee** creates an intent for an exact destination amount.
- **Payer** accepts a source amount and authorizes it.
- **Provider** quotes and, outside this sandbox, would execute a leg under its own authority.
- **Router** compares offers without taking custody.
- **Verifier** checks packet integrity, expiry, replay status, and receipt evidence.

## State machine

`open → quoted → selected → held → authorized → settled`

Terminal/exception paths: `expired`, `failed`, `refunded`, and `disputed`. A refund is a new correlated outcome, not deletion of the original receipt. A dispute records a claim and does not itself prove fault or reverse value.

## Payment Intent

Required fields: `id`, `amount`, `currency`, `merchantId`, `createdAt`, `expiresAt`, `status`. Amounts must eventually use integer minor units; the 0.1 sandbox uses finite decimal numbers for readability.

## Route Quote

Required fields: `id`, `providerId`, source/destination currency and amount, explicit fee, validity, estimated completion, and availability. Implementations should also expose reliability evidence and material constraints. The reference router minimizes source total, then prefers reliability, then speed.

## Value Packet

The packet claims include protocol version, unique id, cryptographic nonce, `singleUse: true`, intent id, source obligation, destination obligation, route identity, issue time, and expiry. The sandbox hashes canonical JSON with SHA-256 and signs claims with Ed25519.

A verifier MUST reject unsupported versions, expiry, previously consumed nonces, digest mismatch, and invalid signatures. Production designs MUST define key discovery, rotation, revocation, algorithm agility, clock tolerance, durable replay protection, and privacy-preserving identifiers.

## Receipt

A settlement receipt identifies the original transaction, final outcome, exact source paid and destination received, packet digest, provider evidence, and issue time. Receipts are append-only evidence; corrections are correlated events.

## Refund and dispute

Refund authorization, FX treatment, fees, and finality are provider/policy concerns exposed through explicit messages. A dispute carries a reason, evidence references, deadlines, and status. VAP must not imply universal chargeback rights.

## Non-goals

VAP 0.1 does not define custody, liquidity, credit, identity verification, compliance policy, legal finality, foreign-exchange licensing, consumer rights, or provider eligibility. It does not create a token or consensus network.

## Open questions

Integer amount representation; privacy envelopes; multi-hop atomicity; quote authenticity; liability allocation; selective disclosure; offline verification; recovery from partial settlement; governance and conformance marks.
